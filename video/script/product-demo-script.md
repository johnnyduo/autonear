# AutoNEAR product demo, final script

Slogan: **Find demand. Build within limits.** (picked from a Codex copy audit; replaces the old 'leash' line). Every shot is the live app (demo data where a wallet or vault is needed), recorded at 1600x900 and shown 1:1. Voice: Gemini 3.8 flash TTS (Puck). 254 spoken words, 1:57. Output: `video/out/autonear-product-demo.mp4`.

## 1. landing

> AutoNEAR finds product ideas in public NEAR activity. Find demand. Build within limits. Here is how it works, start to finish.

## 2. home  ·  chip: LIVE APP · DEMO DATA

> This is Home. Over five hundred public records, from thirteen sources, grouped into seven product ideas. Every record links back to its source.

## 3. watch  ·  chip: LIVE APP · DEMO DATA

> On Watch, you choose the topics, events and words to follow or ignore. Below, every source the agents read, and when it was last checked.

## 4. council  ·  chip: LIVE APP · DEMO DATA

> Then the council votes. Seven specialist agents, one of them a skeptic, score each idea. Treasury rebalancing scored eighty. It needed sixty-two. That is a go.

## 5. build  ·  chip: LIVE APP · DEMO DATA

> From a go, the agents draft the product's landing page: copy, layout, style, checks. You review it, then approve it.

## 6. approvals  ·  chip: LIVE APP · DEMO DATA

> Actions that cost money or go live show up here as cards: what it does, what it costs, when it expires. In Manual mode, you hold to approve. In Auto mode, the agent acts inside your limits.

## 7. vault  ·  chip: PUBLIC TESTNET · DEMO DATA

> The vault holds the agent's budget on NEAR: half a NEAR per action, two a day, ten in total, and an expiry date. The blockchain enforces those limits, not our server. Go outside them, and the transaction is refused.

## 8. proof  ·  chip: RECORDED RUN · NEAR TESTNET · DEMO KEY

> Activity logs every step: the agent starting, fuel taken, a payment refused for being over the limit. Below it, a recorded run on NEAR testnet, each step with its transaction hash.

## 9. close

> That is AutoNEAR. It reads public NEAR demand, scores the ideas, and prepares the builds. Find demand. Build within limits. The code is open. Clone it, run the tests, try the demo.
